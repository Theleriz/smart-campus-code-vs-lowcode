# Reflection

**What AI generated.** An AI coding assistant wrote most of the feature from my brief (based on the course's suggested implementation prompt): the reason codes added to the rule engine, the request and output contract with validators, the prompt, the mock and HTTP adapters, the server endpoint, the explanation panel, the tests and the first versions of these documents. A second, separate AI agent did the read-only code review.

**What I verified.** I made a git checkpoint first and recorded the baseline (26 tests, lint, typecheck, build). After the change I re-ran all four commands, and the 26 old booking tests still pass without edits. I ran the UI in Edge for 11 scenarios, including timeout, API error, a hallucinated answer and a missing key. In every case the confirmed status before and after "Explain" was identical. I checked that no key or `LLM_` variable ends up in the built bundle. For the review, I did not accept any finding without evidence. I turned F1, F2 and F8 into failing tests (9 failed) before changing code, and I rejected F13's claim that the mock is not recognisable, because the UI shows a "Mock AI" badge.

**What I changed.** I fixed the two most important confirmed findings in the output validator: it now requires the confirmed status and the correct reason, and it rejects invented names and Unicode tricks. I rewrote one test that only appeared to prove the rules were unchanged (F9). The remaining findings are documented as open, with reasons.

**What I learned.** The LLM should *explain* availability but never *decide* it. The rule engine is deterministic, testable and cheap, while a model can be confidently wrong. My own tests passed because I tested the validator with my own wording. The agentic reviewer found the gaps by attacking it with paraphrases. A linter would not find these, because they are about meaning, not syntax. AI findings are hypotheses until a test reproduces them. When the model is unavailable, the app should behave as if the feature did not exist: show the confirmed status and a plain, rule-based sentence.
